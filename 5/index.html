B2.2: Training the UNet

To train, the UNet takes in a noisy image xt and a timestep t and predicts the flow x1 - x0. Additionally, the TimeConditionalFM wrapper implements the training algorithm by building xt according to the equation given in the spec, namely xt = (1 - t)x0 + tx1. The training loop then gives the wrapper images and trains via updating the UNet with Adam. The reason time conditioning works is because it tells the model how far the image is from pure noise vs a real image, and this way it's easier to predict the flow at that point. Near the beginning, the image is mostly noise, so the correct direction might be very different than what it is near the end, when the image has very little noise. B2.5: Training the UNet

For class conditioning, the UNet takes in a noisy image, a timestep, and a class label (which is converted to a one hot vector), and it predicts the flow x1 - x0. During the training, the images and labels get passed into the ClassConditionalFM wrapper, which trains via the same linear formula as before, xt = (1 - t)x0 + tx1. However, this wrapper also conditions the UNet on the class which corresponds to the actual digit. This helps the model accuracy a lot, since it knows specifically which digit to generate. Below is the loss.

B2.6: Sampling the UNet

To sample, the model starts with pure noise and predicts both an unconditional and a class-conditional flow at each time step. Then, it combines the two using the formula combination = uncond + γ(cond - uncond), with γ = 5.0. The sample is updated each timestep using the formula xt+1 = xt + (1/T) * combination. Repeating this process each time step guides the flow to a digit who's class matches the input, and the model output looked significantly better than before, as seen below.

To remove the learning rate scheduler, I had to lower the fixed learning rate in the optimizer. The scheduler was used to gradually reduce the learning rate during training, so the average learning rate was smaller. Therefore when removing the scheduler, I had to decrease the optimizer's learning rate to avoid having the learning rate be high for all steps.
